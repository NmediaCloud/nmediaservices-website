Digitising a book is not one problem, it is five, and only the last one is OCR. The pages are photographed rather than flat-scanned, lit unevenly, bound in spreads, and printed in a script that most OCR engines were never trained on. This toolkit walks all five stages, and each one is a self-contained file you double-click. There is no project to build.

02Why the Sanskrit step exists

Tesseract is good at Latin script and much weaker on Devanagari. Ligatures, conjunct consonants and the headline stroke running across an entire word defeat engines trained mostly on English. Add material that is old, foxed and photographed rather than flat-scanned, and standard OCR returns something between unusable and actively misleading.

Unusable is obvious and therefore safe. Actively misleading is the dangerous one: plausible text, quietly wrong, buried in a searchable PDF nobody proofreads.

03Two passes, neither trusted

So Devanagari gets two independent passes, a vision-language model and EasyOCR, and neither is trusted on its own. Where they agree, confidence is high. Where they disagree, that disagreement is the useful output: it marks the pages a human should look at.

"Disagreement between two engines is information. Silently picking one of them is how an error gets archived."

This is the same principle as the vision-graded QA pass elsewhere in the Nmedia pipeline. An automated stage that cannot tell you when it is unsure is a stage you cannot leave unattended.

04Built to be handed over

Every stage is a self-contained batch file with the Python and PowerShell embedded, tied together by a control panel. Drop scans in a folder, expand a stage, move the sliders, save and run. It is meant for an archivist or a librarian rather than an engineer, which is why there is nothing to install per project and nothing to configure in code.
